# Agent instructions

## Communication style

Be concise: no filler, no restating the obvious. Use plain language: short sentences, active voice, common words over jargon (see ISO 24495-1 plain-language principles).

## Context registry

Standards and guidance live in `docs/docs/context-registry/`. Treat it as the source of truth for how things should be done.

## Skills

Skills are authored in `skills-src/`. `.github/skills/` (Copilot) and `.claude/skills/` (Claude Code) are generated by `pnpm build:skills` and gitignored — never edit them directly.

When using a skill, read the entire SKILL.md before making changes.

## Skill freshness and approval check

Each skill is evaluated separately. An eval run committed as a `with_skill` stamp in `skills-src/<skill>/evals/stamps.jsonl` is an **approval** of that skill for a specific context version and model.

Whenever you use a skill, run its check first and pass your own model id:

```bash
node scripts/skill-check.js <skill-name> --model <your-model-id>
```

Read the `STATUS:` line and act on it:

- **APPROVED** — proceed silently.
- **STALE** / **NO_BUILD** — the built skill is behind its sources (or was never built). Tell the user to run `pnpm build:skills` and restart before relying on the skill.
- **UNAPPROVED** — no committed stamp matches this skill's current context hash and your model. Tell the user the skill is unevaluated for the current context/model and ask before relying on it.

Only warn the user for STALE, NO_BUILD, or UNAPPROVED. When the status is UNAPPROVED, check the listed stamps yourself before warning: model names may be written differently between your id and the stamp (e.g. `claude-sonnet-4-5` vs `asserted:claude-sonnet-4.5`). If a listed stamp is plainly the same model at the current context hash, treat it as approved.
